# Roadmap

The roadmap prioritizes trust and maintainability over catalog size. It describes direction, not release promises
or deadlines.

## Now — establish a dependable review loop

- Make suggestion and review workflows understandable in under ten minutes.
- Keep generated navigation, profile schema, and contributor guidance synchronized.
- Maintain a small featured set that demonstrates evidence quality across different resource types.
- Document review freshness and make stale evidence visible.

## Next — deepen trust signals

- Define a lightweight stale-review policy based on risk and source volatility.
- Add reviewer guidance for MCPs, agents, frameworks, and prompt-only resources when real candidates require it.
- Identify narrowly scoped `good-first-issue` tasks that improve existing evidence or documentation.
- Establish a repeatable release-note cadence only when changes justify releases.

## Later — grow without losing quality

- Explore structured schema evolution only after recurring profile needs are demonstrated.
- Consider multilingual navigation when maintainers can review translations reliably.
- Evaluate limited, cached external-link monitoring without executing cataloged software.
- Publish aggregate insights only when the dataset is large and consistent enough to support them.

## Explicit non-goals

- Bulk importing indexes or marketplaces.
- Ranking projects by popularity alone.
- Installing, executing, proxying, or launching cataloged tools.
- Automatically approving compatibility or safety.
- Adding dashboards, databases, or services before static documentation becomes insufficient.

Proposals should explain user value, maintenance cost, privacy impact, and why a simpler documentation change is not
enough. See [PROJECT_VISION.md](PROJECT_VISION.md) for the long-term criteria.
