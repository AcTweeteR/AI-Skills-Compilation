# Changelog

This file records user-visible repository changes. The project follows the structure of Keep a Changelog but does
not claim a release version until one is intentionally published.

## Unreleased

### Added

- Evidence-first catalog navigation by use case, AI environment, category, publisher, status, risk, language, and
  review date.
- Structured issue forms, a pull request checklist, support routing, roadmap, vision, and growth report.
- A repository-local banner and verifiable GitHub badges.
- Offline Markdown structure checks alongside existing catalog validation.

### Changed

- Reorganized the README around first-visit comprehension, featured reviews, trust signals, and a sub-ten-minute
  contribution path.
- Extended profiles with source-owner and content-language metadata without inferring implementation details.

### Security

- Kept all catalog and Markdown checks offline and preserved the rule that cataloged software is never executed.

When a release is created, move relevant entries from `Unreleased` into a dated version section. Do not add empty
or speculative release sections.
